# Step16 descriptor-pinned helper implementation review

## Review status and predecessor

This repository-only implementation-review package is bound to predecessor `0b383e6b9ff71b51b95f422a69048f58a13f0d1d` and its Step16 activation design. It is **non-authoritative**: it authorizes no host inspection, canonical-root selection, owner validation, active-header replacement, compiler execution, wrapper invocation, endpoint read, network/RPC, signing, sending, deployment, commit, or publication.

The package is a fail-closed C library, not an activation program. `descriptor_helper.c` intentionally fails compilation unless `STEP16_DESCRIPTOR_HELPER_REVIEW_FIXTURE` is supplied. There is no library `main`; the only executable is the isolated fixture translation unit used by the repository test in a fresh `mkdtemp` tree. The fixture receives sealed repository source bytes solely through a bounded test-process stream, keeps them only in a temporary allocated buffer, and never writes or prints them. It contains no endpoint/secret literals or encoded wrapper source, receives no host descriptor, and emits only fixed nonsecret status lines. The Node test may read repository `native_wrapper.c` as source data for that stream; this repository read does not read a local secret endpoint file.

## Fixed model boundary

The library accepts a caller-retained trusted parent directory FD and an injected authenticated blob-reader boundary. The reader receives expected commit `620dc7dfbce6c831b4755dce6e5776cb613001b8` and must return `resolved_commit`, object ID, and bytes. The helper compares `resolved_commit` exactly to that expected commit **before** accepting an object ID or hashing bytes. It then requires native-wrapper object ID `0e59f37f98e3f6632064b3ade9a133ea24de90da` before verifying complete-byte SHA-256 `6e45dd91c53ba7ac6aa76e2513a55c901d0bff108f7ae579475dceb1c2ee8d76`. Reviewed header bytes are separately sealed to SHA-256 `8f7e430182822e5014f4be39fdb3ac4734e3546df54d5c3e448c0eba5f510814`.

A request contains no caller-provided opaque stage-ID string or authorization boolean. Instead it supplies a non-null trusted opaque-ID issuer context and `issue_opaque_id` callback. The callback fills a bounded `step16_opaque_id` token containing bytes, length, and `issuer_tag`; the helper requires component-safe bytes and exact tag/context identity before building its private `build-stage-` name. It invokes the issuer once per otherwise valid request. This is provenance control, not cryptographic proof: a hostile issuer callback can lie. The issuer and its context are explicitly the trusted boundary and must be independently reviewed by any future gate.

The helper creates the stage beneath only the supplied parent FD using exclusive `mkdirat`, retains its stage FD, and uses descriptor-relative `openat` with `O_CREAT|O_EXCL|O_NOFOLLOW|O_CLOEXEC` for `native_wrapper.c` and `generated_owner_config.h`. Exact-write accounting rejects zero, negative, or over-reported writes while accommodating a genuine short write. Held file descriptors are `fstat`-checked as regular files and re-read for digest verification.

Every owned close and cleanup unlink result is captured. The helper attempts the file unlinks, stage-FD close, and stage-directory unlink even after an earlier failure. If any cleanup operation fails, it returns only `STEP16_DESCRIPTOR_CLEANUP_FAILED` (the opaque `CLEANUP_FAILED` status), never OK and never a more specific result. Injectable close/unlink callbacks exist solely as the review fixture seam; absent callbacks use libc operations.

## Deliberate limits and future gate

This code does not authenticate a real Git object database, validate a canonical root, validate directory ownership/mode, choose entropy, prove opaque-ID independence, establish the caller's parent FD, or establish trust in the issuer callback. Those are explicit future trusted boundaries and this review makes no host-enforcement claim about them.

No active-header replacement exists. No compiler execution exists. `renameat`, `fsync`, compiler argument construction, process launch, output build, output publication, and wrapper execution are explicitly absent from this package. Each requires a separately reviewed and explicitly authorized future gate. The library uses no Git CLI, `/proc`, network API, process/exec API, endpoint handling, or filesystem lookup beyond descriptor-relative operations on its supplied FD.

## Fixture evidence

`tests/v2-r1-step16-descriptor-helper.test.mjs` lexically rejects native process/network/Git/path surfaces and rejects endpoint pathname fragments, hostname fragments, native-wrapper source markers, and large numeric byte-array payloads from the fixture. It confirms production compilation fails without the fixture macro, builds only the fixture in an `mkdtemp` directory, reads repository `native_wrapper.c` only as test source data, and transfers those bytes on fixture stdin. The fixture enforces a bounded declared length, exact stream accounting, and EOF immediately after the supplied bytes; absent, short, or extra/malformed transfers receive only a fixed opaque rejection status. The fixture demonstrates: the request cannot supply an ID field; issuer invocation is once; wrong issuer provenance is refused; object mismatch; an intentionally digest-invalid resolved-commit mismatch that performs no write and leaves no stage; digest mismatch by mutating a post-stream in-memory byte; short and over-reported writes; preexisting and symlink stage names; symlink source/header entry resistance through no-follow creation; ordinary removal of the complete stage; and synthetic close and unlink failures returning `CLEANUP_FAILED`. Passing this fixture confirms only the modeled review primitive, never host authority or activation authority.
